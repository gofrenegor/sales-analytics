# Аналитика списаний

FastAPI, PostgreSQL и статический интерфейс. Локальный запуск: `sh run.sh`.
Подключение к БД: `DATABASE_URL`, затем `[database].connection_string` в
`secrets.toml` или `.streamlit/secrets.toml`. См. `secrets.toml.example`.
Карта компонентов: `.cursor/rules/map.mdc`.

## Обновление сервера

```sh
cd /var/www/sales-analytics && git pull --ff-only
systemctl restart sales-analytics
```

Зависимости в этом обновлении не изменены. При старте автоматически добавляется
таблица `access_sessions` с индексами; существующие пользователи, пароли и потери
сохраняются. После обновления необходимо войти заново: старые cookie `access_id`
больше не являются подтверждением личности.

Сессия действует 30 дней. В БД хранится SHA-256 случайного 256-битного токена.
Выход отзывает токен на сервере. Смена пароля отзывает все сессии пользователя и
выдаёт новую текущему браузеру. Secure выставляется автоматически для HTTPS-запроса.
За локальным reverse proxy нужно передавать `X-Forwarded-Proto`; Uvicorn должен
доверять только своему прокси. Для сайта, который всегда использует HTTPS,
можно явно задать `AUTH_COOKIE_SECURE=1` в окружении systemd. На HTTP с такой
настройкой браузер не отправит cookie.

Если у первого администратора ещё нет контактов/пароля или пароль забыт,
выполните на сервере из папки проекта:

```sh
venv/bin/python manage_access.py
```

Телефон, почта и новый пароль вводятся интерактивно. Пароль не выводится и не
передаётся аргументом командной строки. Команда меняет учётные данные ID 1 и
отзывает все его сессии. Для обычного обновления её выполнять не нужно.

## Скорость и наблюдаемость

- Bootstrap возвращает пользователя и кэшированную сводку одним запросом.
  Список сотрудников и проблемные ряды загружаются независимо от складского отчёта.
- Кадры ограничены 128 МиБ и 64 ключами; готовый JSON — 32 МиБ и 256 ключами.
  TTL — час, вытеснение по LRU. Сводка живёт 60 секунд. Импорт и очистка
  инвалидируют кэши. Лимиты оценивают хранимые данные, а не полный RSS процесса.
- Одновременные обращения за одним отсутствующим отчётом используют один расчёт.
  Графики блоков и страницы блоков разделяют вычисленные ряды внутри отчёта.
- Устаревшие запросы браузера отменяются, однако уже начавшееся вычисление
  Python может продолжаться. Детали сотрудника выводятся порциями по 100 строк.
- Справочник загружается при открытии панели «Инфо». Подсказки графиков обновляются
  не чаще кадров браузера. Формат JSON и правила классификации сохранены.
- Заголовок `X-Cache` у отчётов: `HIT` — готовый ответ, `MISS` — построение.
  `Server-Timing` показывает `app` (до начала передачи тела), `summary`, `load`
  (SQL и подготовка кадра), `compute` (построение складского отчёта), `json`.
  Некоторые этапы вложены друг в друга; складывать их как независимые нельзя.
  Сравнивайте одинаковый период до/после прогрева. Для времени сети и отрисовки
  нужны отдельно Network/Performance браузера. Запросы дольше секунды пишутся
  логгером `losses` на уровне INFO без контактов, паролей, токенов и query string;
  для записи этих событий настройте уровень INFO у этого логгера.

Для оценки эффекта нужны реальные размеры базы, планы SQL и замеры при нескольких
пользователях. Проценты ускорения без этих данных не заявляются.

## Импорт и ограничения запуска

Superset обновляет совпавшие потери по ШК, ID сборщика и ID сотрудника статуса
перед списанием. Новая строка заменяет прежнюю целиком, включая `posted` и
`status_after`; пустое МХ сохраняется из базы по ШК. Новые потери добавляются,
отсутствующие в файле остаются. ШК обязателен для каждой строки. Для обновления
оприходования старых потерь выгружайте их даты повторно: выгрузка только за
сегодня не обновит вчерашнюю потерю, если её нет в файле. Более старый файл,
загруженный позже, также заменит строку: версии выгрузок не сравниваются.

Куски по 256 КиБ отправляются с параллелизмом 3; временные ошибки повторяются до
трёх попыток. Ограничения: 20 файлов/80 МиБ на загрузку, 80 МиБ всех сохранённых
кусков и 8 загрузок на процесс; preview до 128 МиБ DataFrame/8 записей. Preview
принадлежит создавшему его администратору и истекает через 30 минут. Незавершённые
загрузки очищаются при последующих обращениях. При разборе/сборке Excel есть
дополнительные временные расходы памяти. Перезапуск удаляет незавершённые загрузки.

Оставьте **один Uvicorn worker**: сессии находятся в БД, но uploads/pending,
блокировки записи и инвалидация кэшей пока локальны процессу. Перед несколькими
workers нужны общее хранилище загрузок и согласованная инвалидация кэшей.
Очередь фонового импорта, PostgreSQL COPY и предрассчитанные агрегаты — следующий
этап после замеров. Не включайте GZipMiddleware: существующий прокси некорректно
обрабатывает уже сжатые API-ответы.

## Проверки

Тесты находятся в `tests/`. По правилу проекта они запускаются только по отдельному
запросу. В обновление добавлены регрессии безопасных сессий, кэша и истечения preview.
Для явного запуска потребуется pytest и httpx вместе с зависимостями проекта:

```sh
python -m pytest tests
```
